### Migration guidance for CANDIDATE_LOW items

**ChainId / SUPPORTED_CHAINS / validateChainId:**
If ADR-0006 is validated, ChainId may migrate from integer (EIP-155) to a CAIP-2
string format (e.g., `"eip155:1"` instead of `1`). Implementations should:
- Wrap ChainId access behind an abstraction layer
- Be prepared for string ChainId values in future releases
- Test chain identifier handling with both integer and string formats

**ERROR_HTTP_STATUS / ERROR_RETRYABLE:**
HTTP status mappings and retryability flags may be adjusted as the API pattern
(ADR-0019) is finalized. Changes will be non-breaking at the type level but may
affect runtime behavior.

## Session 2B Expectations

The following changes are expected in the next release after Session 2B:

1. **CANDIDATE_LOW promotions:** ChainId, SUPPORTED_CHAINS, validateChainId
   promoted to FROZEN (or updated to CAIP-2 format)
2. **New FROZEN schemas:** Up to 13 additional object schemas (SmartAccount,
   Capability, etc.) as GAP-0009 is resolved
3. **New CANDIDATE schemas:** Quote object (ADR-0018), Capability object (ADR-0003)
4. **Event envelope changes:** CloudEvents compatibility refinements (ADR-0014)
5. **Wire-format additions:** Envelope format definitions (ADR-0004)
